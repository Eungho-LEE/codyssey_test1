0. 설치 선택안과 추천

추천 조합

Windows + WSL 2(Ubuntu) + Docker Desktop(WSL 2 연동) + Windows용 VSCode(WSL 확장) + Ubuntu 안의 Git을 추천합니다.

WSL은 Windows에서 Linux를 사용할 수 있게 하는 기능이고, Ubuntu는 그 안에 설치할 Linux 배포판입니다. Docker Desktop은 컨테이너 실행 엔진을 관리하고, VSCode는 파일을 편집합니다. Git은 변경 이력, GitHub는 원격 저장소를 담당합니다.

코드블록 위의 bash는 Ubuntu에서 명령을 해석·실행하는 쉘의 이름입니다. “Ubuntu 터미널용 명령”이라는 표지이며 bash라는 제목 자체를 입력하라는 뜻은 아닙니다. PowerShell에서 wsl로 Ubuntu에 들어갔다면 본문의 mkdir, cd 같은 명령부터 입력하세요. dockerfile·markdown 표시는 터미널 명령이 아니라 파일에 작성할 내용입니다. 컨테이너 내부라고 표시한 구간은 해당 컨테이너 쉘에서 실행합니다.

~는 Ubuntu 사용자 홈, /는 Linux 경로 구분자, .은 현재 폴더, ..는 부모 폴더입니다. 파일명 앞의 점은 보통 숨김 파일 관례입니다. --version처럼 하이픈 두 개는 긴 옵션, -p처럼 하나는 짧은 옵션인 경우가 많지만 같은 -p라도 명령마다 뜻이 다릅니다. mkdir의 -p는 부모 폴더 생성, docker run의 -p는 포트 연결입니다.

각 명령은 입력 후 Enter로 실행합니다. 다음 입력 줄인 사용자@컴퓨터:경로$가 다시 나오면 처리가 끝나고 다음 명령을 기다리는 상태입니다. 출력이 없다는 이유로 같은 명령을 반복할 필요는 없습니다. pwd·ls -la처럼 조회 명령으로 결과를 확인하세요. 파일 입력 중 나타나는 단독 > 줄이나 sudo 비밀번호 대기는 다른 상태입니다.

6. Docker Desktop 설치와 점검

배울 것: Docker CLI는 docker 명령을 받는 도구이고, 엔진은 실제 이미지·컨테이너를 관리합니다. 명령 도구가 있어도 엔진이 꺼져 있으면 실행할 수 없습니다.

  1. Docker Desktop Windows 공식 설치 페이지에서 PC 아키텍처에 맞는 설치 파일을 받습니다.
  2. 설치 옵션에 표시되면 WSL 2 백엔드를 선택합니다. 설치 모드가 제공되면 개인 PC에서는 기본 사용자별 설치가 간편합니다. 화면과 권한 요구는 버전에 따라 다를 수 있습니다.
